# SVN Browser

面向 Windows 的轻量级 SVN 资源浏览器。应用使用 Electron 提供类似文件资源管理器的浏览体验，底层通过 `svn.exe` 直接读取和导出远程仓库内容，不会创建 SVN 工作副本。

## 功能

- 保存、编辑、删除并快速切换多个 SVN 仓库
- 浏览目录和文件，并显示版本号、提交人和提交时间
- 使用面包屑、返回按钮或 `Backspace` 返回上一级
- 在列表视图和图标视图之间切换，视图设置会自动保存
- 使用单击、`Ctrl`、`Shift` 进行多选
- 在图标视图的空白区域拖动鼠标框选资源
- 使用 `Ctrl+A` 全选当前列表中的资源
- 双击目录或选中目录后按 `Enter` 进入目录
- 将单个文件、文件夹或当前目录导出到指定的本地目录
- 使用 `Ctrl+C` 或“复制选中项”准备资源，然后在 Windows 文件夹中按 `Ctrl+V` 粘贴
- 按名称递归搜索整个仓库中的文件和文件夹
- 为不同仓库复用已保存的账号
- 查看、清理复制操作产生的本地缓存
- 自动检测、内置或手动选择 SVN 命令行客户端

## 快速开始

环境要求：

- Windows 10/11
- Node.js 和 npm

安装依赖并启动：

```powershell
npm install
npm start
```

项目当前已经在 `vendor/svn` 中包含完整的 Windows SVN 命令行客户端，因此从源码启动和打包后的应用都会优先使用该客户端，一般不需要另外安装 SVN。

## 基本使用

1. 点击左侧的 `+` 添加仓库。
2. 填写显示名称和 SVN 仓库 URL，例如 `https://svn.example.com/project/trunk`。
3. 公共仓库可以留空账号和密码；私有仓库可输入新账号，或复用其他仓库已保存的账号。
4. 选择仓库后即可浏览、搜索、导出或复制资源。

编辑仓库时，密码输入框留空会保留原密码。删除仓库只会删除本地保存的连接配置，不会修改远程 SVN 仓库。

## 浏览与搜索机制

目录浏览通过以下命令读取当前层级：

```text
svn list --xml <仓库或目录 URL>
```

目录始终排在文件之前，同类资源按中文名称排序。

搜索通过一次递归列表请求扫描整个仓库：

```text
svn list --recursive --xml <仓库 URL>
```

搜索规则：

- 只匹配文件或文件夹的名称，不匹配完整路径
- 不区分大小写
- 最多显示 500 条结果
- 搜索结果会显示资源的完整仓库内路径
- 搜索大型仓库时需要等待 SVN 返回完整的递归列表

## 导出与剪贴板机制

“复制到...”和“复制当前文件夹到...”会调用 `svn export`，把选中的远程资源直接导出到用户选择的目录。目标位置已经存在同名文件或文件夹时，操作会终止，应用不会覆盖已有内容。

`Ctrl+C` 并不是把 SVN URL 写入剪贴板。应用会：

1. 为本次操作创建独立的临时缓存目录。
2. 依次使用 `svn export` 下载选中的文件和文件夹。
3. 将导出后的本地路径写入 Windows 文件剪贴板。
4. 用户随后可在资源管理器中按 `Ctrl+V` 粘贴。

因此，复制大型目录所需时间取决于仓库速度和资源大小。在应用提示复制完成前，剪贴板中不会出现这些资源。

缓存位于系统临时目录下的 `svn-browser-clipboard`：

- 应用启动时立即清理一次，之后每小时清理一次
- 自动删除超过 24 小时的批次
- 总占用超过 2 GB 时，从最旧的非活动批次开始删除
- 正在执行导出的批次不会被自动或手动清理
- 手动清空缓存可能导致已复制但尚未粘贴的资源失效

## SVN 客户端检测

应用按以下顺序查找 `svn.exe`：

1. 设置中手动选择并保存的路径
2. 项目或安装包内置的 `svn/bin/svn.exe`
3. 系统 `PATH`
4. TortoiseSVN 安装目录
5. SlikSVN 安装目录
6. CollabNet Subversion Client 安装目录

TortoiseSVN 的默认安装通常只有图形客户端 `TortoiseProc.exe`，不一定包含 `svn.exe`。如果应用只检测到 TortoiseSVN，可以在左下角设置中手动选择客户端，或打开 Apache Subversion 的 Windows 客户端下载页。

所有 SVN 命令都使用非交互模式执行。配置了账号时，应用会把用户名和密码传给 `svn.exe`，不会弹出终端认证窗口。

## 内置 SVN 客户端

内置客户端目录结构必须保持完整：

```text
vendor/svn/
├─ bin/
│  ├─ svn.exe
│  ├─ *.dll
│  └─ 发行版附带的其他运行文件
├─ Licenses/
└─ 其他发行文件
```

不要只复制 `svn.exe`。它依赖同一发行版中的 DLL、认证组件和其他运行文件。`npm run pack` 和 `npm run dist` 会将整个 `vendor/svn` 复制到应用的 `resources/svn` 目录。

更换内置发行版后，应保留其许可证和 NOTICE 文件，并在干净的 Windows 环境中验证实际需要的协议，例如 HTTPS、账号认证和 `svn+ssh`。

## 数据与安全

仓库配置和应用设置保存在 Electron 的 `userData/data.json` 中，包括：

- 仓库名称、URL 和用户名
- 加密后的密码
- 手动选择的 `svn.exe` 路径
- 上次使用的视图模式

密码通过 Electron `safeStorage` 使用操作系统提供的加密能力加密后落盘。仓库列表和渲染进程接口不会返回密码；只有主进程在执行 SVN 命令时读取并解密凭据。

渲染进程启用了 `contextIsolation`，并关闭了 Node.js 集成。文件系统、凭据、SVN 命令和系统剪贴板操作统一由主进程通过受限 IPC 接口处理。

## 测试与打包

运行测试：

```powershell
npm test
```

生成未安装的打包目录：

```powershell
npm run pack
```

生成 Windows NSIS 安装包：

```powershell
npm run dist
```

安装包允许用户选择安装目录。
